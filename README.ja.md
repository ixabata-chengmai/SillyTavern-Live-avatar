# Live Avatar Generator (SillyTavern拡張)

[English README is here](README.md)

チャットの進行に合わせて、LLMにシーン/表情を説明させ、ComfyUI(または標準の画像生成設定)で
画像を生成し、画面右下の専用パネルにアバターとして描画する拡張機能です。

## インストール

1. この`live-avatar`フォルダごと
   `SillyTavernのインストールフォルダ/public/scripts/extensions/third-party/live-avatar`
   にコピーしてください。
2. SillyTavernを再起動(またはページをリロード)します。
3. 拡張機能パネル(魔法の杖アイコン → Extensions)を開き、`Live Avatar Generator`が
   一覧に出ていることを確認します。
4. ドロワーを開いて「有効化」にチェックを入れます。

## ComfyUIを直接使う場合(生成設定ソース = カスタム)

1. ComfyUIをCORSを許可した状態で起動してください。
   ```
   python main.py --enable-cors-header
   ```
   これがないとブラウザ(SillyTavern)からComfyUIへ直接アクセスできません。
2. 設定パネルの「ComfyUI URL」に接続先(例: `http://127.0.0.1:8188`)を入力し、
   「🔄 取得」ボタンを押すとサンプラー・スケジューラー・チェックポイント・VAEの
   一覧がComfyUIから自動取得され、ドロップダウンに反映されます。
3. 「ワークフローJSON」欄に、ComfyUIの `Save (API Format)` で書き出した
   ワークフローJSONを貼り付けるか、ファイル選択で読み込んでください。
   以下のプレースホルダに対応しています(使わないものは省略可):

   ```
   %prompt%  %negative_prompt%  %seed%  %steps%  %scale%
   %sampler% %scheduler% %model% %vae% %width% %height%
   %denoise% %clip_skip%
   ```

   ※ `%denoise%` `%clip_skip%` は今回いただいたサンプルワークフローには
   接続先ノードが無いため、設定値は保存されますが生成には反映されません。
   反映させたい場合は、ワークフロー側で該当ノードの値をこれらのプレースホルダに
   置き換えてください(CLIP Skipなら `CLIPSetLastLayer` ノードの追加が必要です)。

## 標準の画像生成設定をそのまま使う場合(生成設定ソース = 標準)

- SillyTavern標準の「Image Generation」拡張(ComfyUIソース)側で
  ComfyUI URL・ワークフロー・モデル等を設定しておいてください。
- このLive Avatar拡張は内部で `/imagine (プロンプト)` を実行するだけなので、
  標準パネルの設定を変更すればそのまま反映されます。

## 主要設定項目

| 項目 | 説明 |
|---|---|
| キャッシュ | ONで同じ感情タグの組み合わせを再利用(高速)。OFFで常に最新状態を再生成 |
| 最短生成間隔(ms) | 直前の生成からこの時間が経つまで再生成しない。0で無効 |
| 本文差分しきい値 | 直前メッセージとの文字数差がこの値未満なら再生成しない。0で無効 |
| 中断制御 | 新しいメッセージが来たとき、進行中の古い生成をキャンセルするか |
| タイムアウト(ms) | 生成が固まった場合に強制中断するまでの時間 |
| Seed | 0以上の値を入れると毎回同じSeedで生成(キャラの一貫性重視)。**-1でランダム化** |
| キャラクター別オーバーライド | 話者名(`name`)ごとにチェックポイント/プロンプト接頭辞を切り替え |
| 直近参照件数 | ステージ1で「前回の状態」とあわせて渡す直近メッセージの件数。1件だと変化が激しくなりすぎるため、数件まとめて渡すことを推奨(デフォルト5件) |
| 圧縮ステージのテンプレート/指示文 | ステージ1(状況の圧縮・更新)用。トークン: `{{instruction}} {{character_card}} {{previous_context}} {{recent_log}} {{speaker}} {{char_*}}` |
| 圧縮結果の最小文字数 | ステージ1の応答がこの文字数未満なら破棄し、前回の状態を維持したままステージ2に渡す(0で無効、デフォルト20文字) 

## 初期値

- Steps: 12
- CFG Scale: 1.0
- 解像度: 1024 x 1024
- Denoise: 1.0(ワークフロー側で既に固定値のため実質常時有効)
- CLIP Skip: 1(現ワークフロー未接続)
- Seed: 0(固定。ランダム化したい場合は -1 を指定)

### アバターパネルの自由移動
パネル上部のヘッダー部分(名前が表示されている帯)をドラッグすると、画面上の好きな位置に
移動できます。移動した位置は自動的に保存され、次回起動時にも復元されます。
「位置をリセット」ボタンで元の右下固定位置に戻せます。

### 画像未生成時のプレースホルダー
まだ一度も画像を生成していない場合や、画像URLの読み込みに失敗した場合は、
ブラウザ標準の「画像が見つかりません」アイコンではなく、
パネル内に「画像が未生成です」/「画像の読み込みに失敗しました」という
テキスト表示が出ます。

### プロンプトの並び順(テンプレート)のカスタマイズ
設定パネルの「プロンプト構成」欄で、LLMに送る内容の並び順を自由に指定できます。

```
{{instruction}}

{{character_card}}

---
{{log}}
---
```

が初期値です。使用できるトークンは以下の通りです。

| トークン | 内容 |
|---|---|
| `{{instruction}}` | 生成指示文(下記「生成指示」欄。未入力時は既定の指示文) |
| `{{character_card}}` | キャラクターカードの Name/Description/Personality/Scenario をまとめたブロック |
| `{{log}}` | 直近の会話ログ |
| `{{speaker}}` | 現在発言しているキャラクター名 |
| `{{char_name}}` | キャラクター名のみ |
| `{{char_description}}` | Description のみ |
| `{{char_personality}}` | Personality のみ |
| `{{char_scenario}}` | Scenario のみ |
| `{{char_mes_example}}` | Message Example のみ |

`{{character_card}}` を使わず、`{{char_description}}` 等を個別に好きな順番で
並べることも可能です(例: `{{instruction}}\n{{char_personality}}\n{{log}}`)。

### 生成指示(instruction)の任意入力
「生成指示」欄に文章を入力すると、それがLLMへの指示文として使われます。
**空欄の場合は既存の既定指示文(英語のDanbooruタグ抽出指示)がそのまま使われます。**
指示文の中でも `{{speaker}}` `{{char_name}}` などのトークンが使用できます。

## 直近の修正(キャラクターカードのマクロ解決・改行の扱い)

**「入るべき場所に{{user}}:と入る」件の原因**:キャラクターカードのDescription/Personality/
Scenario/Message Exampleには、`{{user}}`(ユーザーのペルソナ名)や`{{char}}`(キャラクター名)
といったSillyTavernの組み込みマクロがそのまま書かれていることが非常によくあります
(例文が `{{user}}: こんにちは\n{{char}}: やあ` のような形式で書かれているなど)。
本拡張はキャラクターオブジェクトから生のテキストを直接読んでいたため、これらのマクロが
解決されないまま`{{user}}:`という文字列としてLLMへの送信テキストに残ってしまっていました。

対策として、キャラクターカードの各フィールドを読み込む際に`SillyTavern.getContext().substituteParams`
(利用可能な場合)、無い場合は`name1`(ユーザー名)・`name2`/キャラクター名を使った簡易置換で、
`{{user}}` `{{char}}`を実際の名前に解決してから使用するようにしました。

**改行の扱い**:以前は改行を` / `に置き換えていましたが、実際の改行文字(`\n`)のままで
`/genraw`に問題なく渡ることが確認できたため、` / `への変換をやめ、`\r\n`/`\r`を`\n`に
正規化するだけの処理に変更しました(`{` `}` `|`のエスケープは引き続き行います)。

## 動作の流れ

1. AIメッセージが描画される(`CHARACTER_MESSAGE_RENDERED`イベント)
2. スロットリング/中断条件をチェック
3. **ステージ1(状況の圧縮・更新)**: そのキャラクターについて保存済みの「圧縮コンテキスト」
   (服装・体型・ポーズ・状況をまとめた説明文)と、直近N件(設定可能)の会話を`/genraw`でLLMに渡し、
   「変化した部分だけ更新した」新しい圧縮コンテキストを生成させる。結果は保存される。
4. **ステージ2(プロンプト生成)**: 更新後の圧縮コンテキストを`/genraw`でLLMに渡し、
   Danbooruスタイルのタグ(画像生成プロンプト)を出力させる。
5. 返ってきたタグをComfyUI(またはstandardモードなら`/imagine`)に渡して画像生成
6. 生成された画像を画面右下の専用パネルにクロスフェードで表示

### 圧縮コンテキストの保存

- **保存先**: SillyTavernのチャットメタデータ(`chatMetadata`)が利用可能な場合はそこに保存されます。
  これはチャットファイルに紐づく標準の永続化領域のため、チャットを閉じて後日再開しても
  (このアプリを再インストールしたりデータをエクスポート/インポートしたりしても)状態が引き継がれます。
  この機能が使えないSillyTavernバージョンの場合は、拡張機能自体の設定領域内にチャットIDをキーとして
  保存するフォールバックを使用します(ブラウザ上で動く拡張機能の性質上、任意のフォルダへ直接
  ファイル出力することはできません)。
- **キー構造**: `チャットID → 話者名 → 圧縮コンテキスト`。グループチャットなど複数キャラクターが
  いる会話では、キャラクターごとに別々の圧縮コンテキストが保持されます。
- **チャット切り替え時**: チャットを切り替えると、そのチャットに保存されている圧縮コンテキストが
  自動的に読み込まれ、続きから状況追跡が再開されます。
- **拡張機能を有効化する前のメッセージ**: 対象になりません。あるチャットでこの拡張機能が
  初めて動作した時点から圧縮コンテキストの追跡が始まります(過去ログをさかのぼっての
  再構築は行いません)。

## 既知の制約

- `/genraw` `/imagine` `executeSlashCommandsWithOptions` はSillyTavern本体のバージョンに
  依存する内部APIです。バージョンによって挙動が変わる場合は、ブラウザのコンソールで
  エラー内容を確認してください。
- カスタムモードでComfyUIに直接アクセスするには、ComfyUI側のCORS設定が必須です。
